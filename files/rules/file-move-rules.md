# file-move-rules — 볼트 파일·폴더 이동 규칙

> 정본. 에이전트가 볼트에서 파일이나 폴더를 옮길 때 반드시 따른다.
> 근거 사고: 2026-08-23, 9yohan 정본을 `00. Inbox/…/2026-04-19-9yohan-orchestration/` 에서

> 포인터가 **넉 달간 조용히 죽어 있었다.** 케플러(OpenClaw)가 실제로 그 경로를 열려다 실패해 발견.

## 이동·개명 계약 (2026-09-08 · E08)
이 파일은 파일·폴더 이동과 개명의 정본이다. 삭제 요청은 아래 의존성 검사를 함께 적용하되 별도의 삭제 권한을 확인한다. 기존 세션에서 허용된 작업을 다시 승인받을 필요는 없으며, 허용되지 않은 볼트·파일의 변경까지 확대하지 않는다.

**완료 기준: 선언한 범위에서 이동 대상의 활성 포인터가 깨지거나 다른 대상을 가리키는 경우 0건, 보존 대상으로 분류한 역사·원문 바이트 불변, 검사 누락·미확인 0건.** 옛 문자열의 총 검색 건수는 완료 기준이 아니다.

## 1. 이동 전에 대상·참조·보존 범위를 기록
- 원래 볼트와 정확한 파일/폴더 경로 → 대상 볼트와 새 경로의 매핑을 만든다. 파일 해시·권한·기존 변경 상태를 기록하고, 기존 대상 덮어쓰기·동명 충돌·symlink 경계를 먼저 확인한다.
- 조사한 볼트·폴더·파일 유형, 제외 범위, 읽기 실패를 남긴다. 참조 후보는 옛 상대경로·basename·절대경로·URI 인코딩 경로를 함께 찾고, 해당 작업의 닷폴더·runtime 설정도 포함한다. 문자열 일치 하나가 의도한 파일의 참조임을 보장하지 않으므로 앞뒤 맥락을 확인한다.
- 검색은 rg의 고정 문자열 검색(-F) 등을 사용한다. 검색 실패·무시된 파일·아직 확인하지 않은 표면을 0건으로 취급하지 않는다. 후보 검색 0건만으로 이동을 결정하지 않는다.
- 파일별이 아닌 **참조·구역별 ledger**에 위치, 역할(active/history/raw/seed/unresolved), 원래 대상, 바꿀 대상 또는 보존 이유, 검증 결과를 남긴다. 인덱스·MOC·시스템 안내·runtime 진입점의 현재 포인터를 우선 확인한다.
- 이동되는 문서 자신이 가진 상대경로 참조도 조사한다. 참조받는 쪽뿐 아니라 @./·@../ import, 상대경로 링크·이미지의 기준 위치가 바뀌는 경우까지 포함한다.

## 2. 참조 형태별 판정
같은 basename의 파일이 존재한다는 사실보다 **의도한 동일 대상**이 유지되는지가 중요하다.

| 형태 | 이동·개명 시 처리 | 보존할 부분 |
|---|---|---|
| basename-only wikilink | 새 위치에서도 동일 대상임을 확인한 경우만 문자열 유지 가능. 동명·해석 불명확이면 자동 통과시키지 않고 의도 확인 후 경로형으로 한정 | 표시 alias·heading·block |
| 경로형 wikilink·임베드 | basename이 같아도 옛 경로가 유효한지 확인하고 의도한 새 대상의 정확한 경로로 갱신 | ! 임베드 표식·alias·heading·block |
| @import·활성 백틱/설정 경로 | 해당 문서·runtime의 기준 경로에서 정확한 새 대상과 대조. basename 또는 접미사 일치로 대체 검증하지 않음 | import 형식·설정 문법 |
| 이동 문서 내부의 상대경로 링크·이미지·@./·@../ | 문서의 새 위치를 기준으로 다시 해석해 원래 의존 대상을 유지 | 링크/이미지 표식·표시 문자열 |
| 교차 볼트 URI | 지정된 vault와 해당 액션의 filepath 또는 file을 한 번 decode해 실제 대상과 대조. 이동 매핑에 해당하는 경로만 다시 encode | 방향별 필드·표시 라벨·액션·기존 fragment/query 의미 |
| 역사 기록·Raw Source 원문 | 당시 경로·인용·실행 명령을 그대로 보존. 현재 경로 안내가 필요하면 허용된 별도 navigation/정정 기록에 추가 | 보호 파일 전체 또는 보호 구역 바이트 |
| 의도된 미작성 씨앗·미확인 참조 | seed는 생성·삭제·재연결하지 않음. unresolved는 확인 전 자동 치환·완료 판정 금지 | 기존 의도·판단 근거 |

- Obsidian에서 이동하더라도 자동 링크 갱신의 실제 결과를 확인한다. 셸·스크립트 이동은 앱의 자동 갱신을 기대하지 않는다.
- 경로형 링크의 #heading, #^block-id와 alias를 유지한다. alias에 옛 이름이 남아도 활성 대상이 정확하면 정상이다. 표 안의 alias 구분자는 기존 이스케이프를 보존한다.
- URI의 정본은 [[90. Settings/94. Agent Settings/claude/rules/wikilink-rules|wikilink-rules]] §6이다. 마더십 wikiVaultRelated와 위키 mainVaultRelated를 구분하며, 반대 볼트에 같은 경로가 있다는 이유로 지정 볼트의 오류를 통과시키지 않는다.
- 다른 볼트의 활성 참조를 발견한 사실이 그 볼트의 쓰기 권한을 만들지는 않는다. 허용 범위에서 처리하고 미수정 활성 참조는 잔여로 보고한다. 필요 범위가 미해결이면 전체 이동 정리를 완료로 표시하지 않는다.

## 3. 역사·원문 보존
- 데일리·위클리·발행·스크래치·감사 기록의 “그때 그랬다” 구역은 보존한다. 같은 파일의 “지금 여기를 보라” navigation은 별도 active 구역으로 분류할 수 있다. 폴더명만으로 파일 전체를 일괄 제외하거나 치환하지 않는다.
- 역사 전용 파일은 전체 해시, 현재 navigation이 섞인 문서는 보호 구역의 정확한 바이트와 위치 근거를 보존한다. active 구역을 바꾼 혼합 문서에 전체 파일 해시 불변을 요구하지 않는다.
- Raw Source의 원문·인용은 경로 문자열이 들어 있어도 바꾸지 않는다. 원문 밖 metadata 변경도 해당 볼트의 불변성·승인 계약 범위 안에서만 수행한다.
- 검사기의 0건을 만들려고 보존 원문에 ignore 주석을 넣거나 과거 명령·경로를 새 값으로 소급 치환하지 않는다. 역사 예외와 당시 경로 → 현재 경로 매핑은 이번 작업의 별도 ledger/로그에 기록한다.

## 4. 적용
1. 원본·보호 구역·매핑이 검토 당시와 같은지 다시 확인한다. 후속 편집이 있으면 덮어쓰지 않고 차이를 반영한다.
2. 허용된 대상만 옮기고 새 경로의 실제 파일과 정체성을 확인한다. 이동 뒤 파일 내용·권한 변화를 기록하며, 필요한 상대 의존성 수정은 별도로 구분한다.
3. 허용된 active 참조만 같은 작업 단위에서 갱신한다. 단순 전역 치환을 사용하지 않는다. 여러 경로 매핑은 긴 경로부터 적용하되 **경계까지 정확히 일치**하는 항목만 바꿔 비슷한 이름의 폴더·다른 대상을 건드리지 않는다.
4. 단계 도중 중단·검증 실패가 생기면 수행/미수행 목록과 깨진 active 참조를 즉시 기록한다. 완료로 표시하지 말고 이번 변경분만 복구하거나 후속 교정을 이어간다.

## 5. 완료 검증과 복원
- 선언한 참조 inventory와 실제 검사 목록을 대조한다. 각 active 참조를 그 볼트·문서·runtime의 기준에서 해석해 **정확한 의도 대상**과 비교한다. 파일이 존재해도 다른 대상이면 실패다.
- 역사·원문 보호 해시와 seed 보존을 확인한다. 옛 문자열 검색 결과는 active 미교정 / history / raw / seed / 표시 alias / unresolved로 설명하며, 총 0건을 요구하지 않는다.
- 검사 누락·읽기 실패·동명 해석 미확인·권한 밖 active 잔여가 있으면 범위와 후속 조치를 적는다. 검증하지 못한 상태를 정상으로 집계하지 않는다.
- before/after 매핑·변경 diff·보호 해시·개별 검증·잔여·복원 경로를 작업 로그에 남긴다. Markdown 변경의 qmd 후처리는 해당 배치의 orchestrator가 수행한다.
- 복원 전에 현재 파일이 after 상태와 같은지 확인하고 이번 변경만 되돌린다. 새로 생긴 같은 경로 파일을 덮어쓰거나 후속 수정까지 지우지 않는다. 복원 뒤 참조와 보호 바이트를 다시 확인한다.

## 기존 경로 감사기의 위치와 한계
기존 `~/.claude/scripts/vault-path-audit.py`는 **보조 감사**다. 실행 범위가 허용된 경우만 사용하며 이번 이동의 완료 판정을 대신하지 않는다.
- 현재 CLI는 --verbose만 제공하고 파일·볼트 범위 인자가 없다. 기본 실행은 메인·위키 전체이며, 임의 경로 인자를 붙여 단일 파일 검사처럼 쓰지 않는다.
- NN. 형식의 백틱/경로형 wikilink를 휴리스틱으로 검사한다. 정확 경로가 없어도 접미사·유일 basename 또는 다른 볼트의 합집합으로 정상 처리할 수 있다.
- 닷폴더·코드블록·import·URI 등의 사각지대가 있고 읽기 실패·제외 항목은 실제 검사 coverage와 구분해야 한다. exit 0은 검사한 휴리스틱에서 발견이 없다는 뜻이며 정확한 active 대상·역사 보존의 증거가 아니다.
- 기존 제외 목록 `~/.claude/vault-path-audit-ignore.txt`는 참고만 한다. 검사를 통과시키기 위한 전역 ignore 추가·원문 변경은 이 이동 계약에 포함되지 않는다.
- 이 정본 갱신은 감사기 코드·주간 스케줄을 수정하거나 앱 자동 실행을 활성화하지 않는다.
