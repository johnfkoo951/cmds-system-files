GUIDE · load order

Who reads what

Nine files, five kinds of readers. Each reader opens one entry file; the rest arrive by @include or by an explicit read when a task calls for them.

Not every agent reads the same files. Claude Code starts from CLAUDE.md, which pulls in CMDS.md and the nine shared rules; Codex, Cursor and Gemini CLI start from AGENTS.md and read the same rules explicitly. Three private files, ANTIGRAVITY.md, BRAIN.md and BRAIN_PROMPT.md, never leave the vault, and people read CMDS Guide and CMDS Head Quarter.에이전트마다 읽는 파일이 다릅니다. Claude Code는 CLAUDE.md에서 시작해 CMDS.md와 공유 규칙 9개를 함께 불러오고, Codex·Cursor·Gemini CLI는 AGENTS.md에서 시작해 같은 규칙을 명시적으로 읽습니다. 비공개 파일 셋(ANTIGRAVITY.md, BRAIN.md, BRAIN_PROMPT.md)은 볼트 밖으로 나가지 않으며, 사람은 CMDS Guide와 CMDS Head Quarter를 읽습니다.

GUIDE · commands

Thirteen commands, three harnesses

Ten CMDS Process commands run the lifecycle and three periodic commands write the daily, weekly and insight notes. The eight core operations are mirrored for Claude Code, Codex and the agents skill folder.

The CMDS Process also exists as slash commands. The eight operating commands (/connect, /merge, /develop, /share, /inbox, /lint, /query, /status) are kept in three parallel forms so any harness can run them: .claude/commands/<op>.md for Claude Code (the .claude/commands/ folder is a symlink to the vault's 90. Settings/94. Agent Settings/claude/commands/), .codex/commands/<op>.md for Codex, and .agents/skills/<op>/SKILL.md as a skill. Five more commands (/seeds, /harvest, /daily, /weekly, /insight) exist only for Claude Code, which brings the total to thirteen.CMDS Process는 슬래시 커맨드로도 존재합니다. 운영 커맨드 8개(/connect, /merge, /develop, /share, /inbox, /lint, /query, /status)는 어느 하네스에서도 쓸 수 있도록 세 곳에 나란히 둡니다: Claude Code용 .claude/commands/<op>.md(.claude/commands/ 폴더는 볼트의 90. Settings/94. Agent Settings/claude/commands/를 가리키는 symlink), Codex용 .codex/commands/<op>.md, 스킬 형태의 .agents/skills/<op>/SKILL.md입니다. /seeds, /harvest, /daily, /weekly, /insight 5개는 Claude Code에만 있어 전체는 13개입니다.

SHARED RULES · .claude/rules/

Shared Rules

Nine atomic rule files. CLAUDE.md pulls them in with @include; other agents read them directly as AGENTS.md instructs. One rule, one concern.

All nine shared rules sit in one folder, .claude/rules/. CLAUDE.md pulls eight of them into every Claude Code session with @include; the ninth, file-move-rules, is imported from inside wikilink-rules. Agents that use AGENTS.md (Codex, Cursor, Gemini CLI) cannot follow @include, so they read the folder explicitly.공유 규칙 9개는 모두 .claude/rules/ 한 폴더에 있습니다. CLAUDE.md는 그중 8개를 @include로 매 Claude Code 세션에 불러오고, 아홉 번째인 file-move-rules는 wikilink-rules 안에서 import됩니다. AGENTS.md를 쓰는 에이전트(Codex, Cursor, Gemini CLI)는 @include를 따라가지 못하므로 폴더를 명시적으로 읽습니다.

GUIDE · vault layout

Where things live

Ten root folders carry the vault. CMDS categories are metadata on top of them, not folders, and agent settings live in one canonical folder that the dot-folders link to.

The vault has ten root folders, 00. Inbox through 90. Settings, and every file lives in one of them; the numbered CMDS category is set separately in frontmatter. Three places matter for agents: the per-agent drafting lanes 03-1 to 03-9 under 00. Inbox/03. AI Agent, the Daily and Weekly logs under 10. CMDS Process/15. Periodic, and the canonical agent settings under 90. Settings/94. Agent Settings/claude. The hidden .claude folder is only a symlink to that last one, so agents, commands, hooks, rules, skills and scripts exist once and sync with the rest of the vault.볼트에는 00. Inbox부터 90. Settings까지 루트 폴더 10개가 있고 모든 파일은 그중 하나에 들어가며, 숫자 CMDS 카테고리는 폴더와 별개로 frontmatter에서 정합니다. 에이전트에게 중요한 자리는 세 곳으로, 00. Inbox/03. AI Agent 아래의 에이전트별 초안 레인 03-1~03-9, 10. CMDS Process/15. Periodic 아래의 Daily·Weekly 기록, 그리고 90. Settings/94. Agent Settings/claude의 에이전트 설정 정본입니다. 숨김 폴더 .claude는 그 정본을 가리키는 symlink일 뿐이라, agents·commands·hooks·rules·skills·scripts는 한 곳에만 있고 볼트와 함께 동기화됩니다.

GUIDE · versions

How this site is built

Edits happen in the vault only. One script checks the gates, syncs eight destinations and deploys this page; versions live on two layers.

This site is not edited by hand. A system file is changed once in the vault, then a sync script runs a gate (dates, version and count audit, frontmatter tags) before copying it to the backup, the sanitized shared copy and the DEV repo. The DEV repo is pushed to GitHub with a tag and Release, and Vercel deploys the same DEV snapshot here. Versions live on two layers: each file carries its own micro version in frontmatter, and the macro version is the top of CHANGELOG.md plus the GitHub Release.이 사이트는 손으로 고치지 않습니다. 시스템 파일을 볼트에서 한 번 수정하면 동기화 스크립트가 게이트(날짜, 버전·카운트 감사, frontmatter tags)를 통과시킨 뒤 백업, sanitized 공유본, DEV 레포 세 곳에 복제합니다. DEV 레포는 GitHub에 태그·Release와 함께 push되고, Vercel이 같은 DEV 스냅샷을 여기에 배포합니다. 버전은 두 층입니다. 파일마다 frontmatter에 마이크로 버전이 있고, 매크로 버전은 CHANGELOG.md 최상단과 GitHub Release가 가집니다.

Layer층Where it is written적히는 곳Bumps when올라가는 때

Micro version마이크로 버전version: in each file's frontmatter, with an inline changelog각 파일 frontmatter 의 version: 과 그 안의 changelogthat one file changes그 파일 하나가 바뀔 때

Before anything is copied, the sync script runs four gates: frontmatter tags must stay inline, the three dates on each file (banner, date modified, newest changelog entry) must agree, the versions and counts quoted across files and on this site must match the vault, and the live site must show the released version afterwards.복사하기 전에 동기화 스크립트가 네 개의 게이트를 통과해야 합니다. frontmatter 의 tags 가 인라인으로 유지되는지, 파일마다 세 날짜(배너, date modified, 최신 changelog 항목)가 맞는지, 파일들과 이 사이트에 적힌 버전·개수가 볼트와 같은지, 그리고 배포 뒤 실제 사이트가 릴리스 버전을 보이는지입니다.
